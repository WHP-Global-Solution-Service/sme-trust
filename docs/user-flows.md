# User Flows & State Machines

## 1. ลงทะเบียนผู้ใช้ (Module A)

```
Welcome → เบอร์โทร (Zod: 0[689]xxxxxxxx + ยอมรับเงื่อนไข)
        → OTP (รหัส Demo แสดงบนจอ, ขอใหม่ได้หลัง 30 วิ, ผิด = OTP Invalid, เบอร์ซ้ำ = แนะนำ Login)
        → ข้อมูลเริ่มต้น (ชื่อ นามสกุล อีเมล จังหวัด)
        → e-KYC จำลอง (คำแนะนำ → ถ่ายบัตร → สแกน → ใบหน้า → สแกน → Verified | Failed → Retry) หรือ "ข้ามไปก่อน"
        → ตั้ง PIN 6 หลัก ×2 (ห้ามเลขซ้ำ/เรียง, ต้องตรงกัน)
        → สำเร็จ → Merchant Home (ไม่บังคับลงทะเบียนร้าน)
```

PIN Login: กรอก 6 หลัก → ผิดแสดงจำนวนครั้งที่เหลือ → ครบ 5 ครั้งล็อก → ลืม PIN (OTP Demo → PIN ใหม่ ×2) · Biometric จำลอง (ปุ่มลายนิ้วมือบน Keypad)

## 2. คำขอลงทะเบียน/รับรอง (Module C, D, E)

```
draft ──ส่ง──▶ submitted ──(เจ้าหน้าที่เริ่มตรวจ)──▶ under_verification ──▶ approved  ⇒ ออกใบรับรอง L2 (หรือระดับที่ขอ)
                   │                                    ├──▶ need_info ──(ร้านส่งข้อมูล)──▶ submitted
                   │                                    └──▶ rejected  ──(ร้านแก้ไข/ยื่นใหม่)──▶ submitted
                   └── pending_review (seed: ผ่านตรวจความครบถ้วนอัตโนมัติ)
```

ใบรับรอง: `active ⇄ suspended → revoked`, `active → expired → (ต่ออายุ) active` · ออกใบใหม่ = ใบเดิมถูกแทนที่ (supersededBy)

## 3. ข้อร้องเรียน (Module H, I, J)

```
ผู้บริโภคยื่น ─▶ Screening (Rule-based) ─┬─▶ awaiting_merchant ─(ร้านเสนอคืนเงิน/เปลี่ยน/ส่งใหม่)─▶ waiting_consumer
                                          │                     └(ร้านชี้แจง/ขอข้อมูล)─▶ merchant_responded
                                          │   waiting_consumer ─ยอมรับ─▶ (รอยืนยัน) ─ยืนยันได้รับการแก้ไข─▶ resolved
                                          │                    ─ปฏิเสธ/ขอเจรจา─▶ merchant_responded ─▶ (ร้านเสนอใหม่)
                                          │   ทุกสถานะที่ยังเปิด ─ผู้บริโภคขอส่งต่อ─▶ escalated
                                          └─▶ escalated ทันที (กรณีเสี่ยงร้ายแรง / ผู้บริโภคเลือก)
escalated ─เจ้าหน้าที่─▶ ส่งกลับร้านค้า (awaiting_merchant) | ปิดเรื่อง (closed)
```

Screening Assistant ตรวจ: คำสำคัญ → หมวดที่แนะนำ, ความครบถ้วน 5 รายการ, คำบ่งชี้อันตราย → urgent, เรื่องซ้ำ (เลขคำสั่งซื้อเดียวกัน หรือผู้ร้อง+ร้าน+หมวดเดียวกันที่ยังเปิด), จำนวนเรื่องค้างของร้าน, มูลค่า → ความสำคัญ เจ้าหน้าที่ปรับหมวด/ความสำคัญได้

## 4. คำแนะนำ / คำเตือน (Module K)

```
Advisory:  advisory ─รับทราบ─▶ acknowledged (หรือ correction_required ถ้ามีรายการ) ─▶ … ─▶ completed
Warning :  warning_issued ─รับทราบ─▶ correction_required ─ส่งหลักฐาน─▶ correction_submitted
                                       ▲                                   │ เริ่มตรวจ
                                       └──────── ส่งกลับแก้ไข ◀── under_review ─ผ่าน─▶ completed
```

ร้านที่มีคำเตือนค้างแสดงสถานะ "มีคำเตือน" (คำแนะนำไม่มีผล) และจะกลับเป็น "ปกติ" เมื่อคำเตือนทั้งหมดเสร็จสิ้นและไม่มีเรื่องความเสี่ยงค้าง

## 5. ความเสี่ยง / ระงับ / อุทธรณ์ (Module M)

```
allegation ─▶ under_investigation ─▶ warning ─▶ suspended ─▶ revoked
     │                │                  │           │           │
     └──── dismissed ◀┴──────────────────┴───────────┘ (คืนใบรับรองที่ถูกระงับ)
suspended/revoked ─ร้านยื่นอุทธรณ์─▶ appeal_submitted ─▶ appeal_reviewed (upheld = คงผล | overturned = คืนสถานะ)
```

- ระงับได้หลังเปิดการตรวจสอบเท่านั้น และต้องระบุเหตุผลทุกขั้น
- ร้านค้าส่งคำชี้แจงได้ตั้งแต่ขั้นข้อกล่าวหา
- หน้าสาธารณะเห็นเฉพาะผลต่อใบรับรอง (ระงับ/เพิกถอน) ไม่เห็นข้อกล่าวหาหรือข้อมูลผู้ร้องเรียน

## 6. การอบรม (Module L)

เริ่มเรียน → เรียนครบทุกบท → แบบทดสอบ (เกณฑ์ 75%) → ผ่าน: ออกเลข TRN, Certificate of Completion จำลอง, บันทึกใน Passport, ติ๊กรายการ "อบรม" ในคำเตือนที่แนบหลักสูตร · ไม่ผ่าน: ทำใหม่ได้ (คะแนนสูงสุดถูกเก็บไว้)

## 7. AI Simulation (ผู้ประกอบการ)

**AI-01 ตรวจสอบข้อความโฆษณา** — `/m/ai/ad-checker`

```
เลือกตัวอย่าง / พิมพ์ข้อความ (10–2,000 ตัวอักษร)
  ─▶ วิเคราะห์ (กำลังวิเคราะห์ ~0.7 วิ) ─▶ ระดับ Low/Medium/High + Highlight + รายการประเด็น
  ─▶ ข้อความเสนอแก้ไข (คัดลอก / แก้ไข / ย้อนกลับฉบับเสนอ)
  ─▶ วิเคราะห์ใหม่เพื่อเปรียบเทียบ ─▶ Before/After
แก้ข้อความต้นฉบับหลังวิเคราะห์ ─▶ แจ้งว่าผลเป็นของข้อความก่อนแก้ไข
```

**AI-02 ช่วยจัดการข้อร้องเรียน** — `/m/ai/complaint`

```
หน้าเคส /m/complaints/:id ─"ให้ AI ช่วยวิเคราะห์"─▶ /m/ai/complaint?case=:id (วิเคราะห์อัตโนมัติ)
  ─▶ ประเภท + ระดับการติดตาม + ประเด็นสำคัญ + ข้อมูลที่ควรขอ + แนวทางแก้ไข
  ─▶ ร่างคำตอบ (Tone / ค่ะ-ครับ / สร้างสำนวนใหม่ / แก้ไข / คัดลอก)
  ─"นำร่างไปใส่ช่องตอบกลับเคส"─▶ หน้าเคส: ช่องตอบกลับมีร่าง + แบนเนอร์ "ยังไม่ได้ส่งถึงลูกค้า"
  ─ร้านค้ากด "ส่งการตอบกลับ" เอง─▶ merchantRespond() ─▶ ผู้บริโภคเห็นคำตอบ
```

- ไม่มีการส่งข้อความหรือเปลี่ยนสถานะเคสโดย AI · "ไม่ใช้ร่างนี้" ล้างร่างออก · ส่งแล้วร่างถูกล้าง
- ทุกการวิเคราะห์เพิ่มประวัติที่ `/m/ai/history` (ล่าสุด 20 รายการ · Clear History · Reset Demo Data คืนตัวอย่าง)
