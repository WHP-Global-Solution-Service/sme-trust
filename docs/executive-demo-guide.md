# Executive Demo Guide — SME Trust

> สำหรับผู้นำเสนอต่อผู้บริหารหรือลูกค้า · ระบบเป็นต้นแบบเพื่อสาธิตแนวคิด ใช้ข้อมูลจำลอง และยังไม่เชื่อมต่อกับ Shopee, Lazada, DBD หรือ สคบ. จริง

## 1. Concept Summary (30 วินาที)

SME Trust คือ **แพลตฟอร์มกลาง** ที่ประเมินความน่าเชื่อถือของผู้ประกอบการ SME จากข้อมูลร้านค้า ตัวตน และพฤติกรรมการขายจากหลายช่องทาง

- ไม่ใช่ Marketplace ไม่ขายสินค้า และไม่รับชำระเงิน
- ร้านมี Marketplace → เชื่อมและเติมข้อมูลอัตโนมัติ · ไม่มี → สมัครเองได้ ไม่ถูกหักคะแนน
- ระบบประเมินและออก **Assessment Badge อัตโนมัติ** — เจ้าหน้าที่ตรวจ **เฉพาะกรณีจำเป็น**
- การรับรองที่ต้องใช้อำนาจ (Level 2–4) ยังเป็นของเจ้าหน้าที่ แยกจากผลประเมินอัตโนมัติ

## 3. Demo Sequence (≈ 20 นาที)

1. **หน้าแรก (2 นาที)** — อ่าน Hero → 5 ขั้นตอน → สองช่องทางสมัคร → Badge และสถานะ (ไม่ต้องอ่านข้อความยาว)
2. **Scenario 14 (4 นาที)** — Marketplace App → เชื่อม → Auto-Fill → ผลอัตโนมัติ AUTO_PASS → Badge → ผู้บริโภคเห็น Badge + QR · *ไม่มีขั้นตอนเจ้าหน้าที่*
3. **Scenario 15 (5 นาที)** — ร้านเชื่อมบัญชีที่ชื่อเจ้าของไม่ตรง → MANUAL_REVIEW → Exception Queue (งานเดียว พร้อมเหตุผลและหลักฐาน) → อนุมัติ → Badge แสดง · ใบรับรองไม่เปลี่ยน
4. **Scenario 9B (4 นาที)** — ร้านไม่มี Marketplace สมัครเอง → Insufficient Data พร้อมคำแนะนำ (ไม่ใช่ผลลบ) → (เสริม) หน้าร้าน "เพิ่มช่องทางขาย" เชื่อม Shopee ภายหลัง → Badge อัปเดตอัตโนมัติ
5. **Officer Dashboard (2 นาที)** — Exception Queue 7 หมวด · KPI จากข้อมูลจำลอง · `/o/automation` นโยบาย Certification
6. **ปิดท้าย (3 นาที)** — Executive Summary (`/demo/v2/summary`) และข้อจำกัดของต้นแบบ

ตัวควบคุมการสาธิตแสดง: ขั้นตอน/ความคืบหน้า · บทบาทปัจจุบัน · บริบท (ร้าน คำขอ งาน) · **ประโยชน์ของขั้นนั้น** · ถัดไป/ย้อนกลับ · Role Transition · Restart · สรุปผลเมื่อจบ

- กด "ถัดไป"/"ย้อนกลับ" ติดกันเร็ว ๆ ได้ — หน้าจอเปลี่ยนตามขั้นเสมอ (แก้ KI-V2-32 แล้ว) · ถ้าเปิดหน้าอื่นระหว่างสาธิต ใช้ "กลับไปหน้าจอของขั้นนี้"
- นำเสนอบนมือถือ/แท็บเล็ต: ตัวควบคุมเป็นแถบด้านล่าง · ปุ่ม "เข้าสู่ระบบ" อยู่ที่ Header ทุกขนาดจอ (Demo Mode เป็นไอคอนรูปขวดทดลองบนจอเล็ก)

### เตรียมก่อนนำเสนอ (5 นาที)

1. เปิด `/demo` → "Reset Demo Data ทั้งหมด" (หรือเปิดเบราว์เซอร์ใหม่) เพื่อเริ่มจากข้อมูลตั้งต้น
2. ตรวจหน้าแรกบนอุปกรณ์ที่จะใช้นำเสนอจริง (ยังไม่ได้ทดสอบบน Safari หรือมือถือจริง — KI-01)
3. ซ้อม Scenario 14 หนึ่งรอบ แล้ว Reset อีกครั้ง

## 4. Presentation Talking Points

- "ลดการกรอกข้อมูลซ้ำ" — ข้อมูลที่มีอยู่แล้วบน Marketplace เติมให้อัตโนมัติ ร้านเห็นและแก้ไขก่อนยืนยันเสมอ
- "ประเมินจากหลายปัจจัย ไม่ใช่คะแนนดาวอย่างเดียว" — ตัวตน พฤติกรรมการขาย รีวิว ราคา การปฏิบัติตามข้อกำหนด + Coverage/Confidence แยกกัน
- "เจ้าหน้าที่ดูเฉพาะกรณีจำเป็น" — ตัวตน/ความเป็นเจ้าของขัดแย้ง สัญญาณหลายข้อ หลักฐานขัดแย้ง และคำขอที่ต้องใช้อำนาจ
- "ผู้บริโภคเห็นข้อมูลประกอบการตัดสินใจ" — Band แหล่งข้อมูล สถานะ Badge และใบรับรอง โดยไม่เห็นคะแนนภายใน
- การแจ้งเตือนความเสี่ยงไม่เท่ากับการตัดสินว่าร้านกระทำผิด
- ร้านที่ไม่มี Shopee/Lazada เข้าร่วมได้และไม่ถูกหักคะแนน

## 5. Expected Results

| ขั้น | ผลที่ควรเห็น |
|---|---|
| Scenario 14 จบ | Badge `active` · ไม่มีงานเจ้าหน้าที่ · ใบรับรอง Level 3 เดิม |
| Scenario 15 หลังอนุมัติ | งาน 1 งาน (อนุมัติ) · Badge `active` · ใบรับรองไม่เปลี่ยน |
| Scenario 15 หลังไม่อนุมัติ | ข้อมูลร้านนั้นไม่ถูกใช้ · Insufficient Data |
| 9B | Insufficient Data + "ไม่ถูกหักคะแนน" · คำขอรอเจ้าหน้าที่ |
| ร้านถูกระงับ/เพิกถอน/คำขอไม่ผ่าน | ไม่แสดง Badge |

## 6. Limitations (ต้องบอกผู้ฟัง)

- ข้อมูลทั้งหมดเป็นข้อมูลจำลอง · ไม่เชื่อมต่อ Shopee, Lazada, DBD หรือ สคบ. จริง · ไม่มี AI Model หรือ e-KYC จริง
- กฎการประเมินและการคัดกรองเป็นค่าตั้งต้นเพื่อการสาธิต ยังไม่ได้ปรับเทียบกับข้อมูลจริง และไม่สามารถตรวจจับการทุจริตได้ทั้งหมด
- ระบบประมวลผลเมื่อมีเหตุการณ์ขณะเปิดระบบเท่านั้น (ไม่ใช่การติดตามแบบ Real-time)
- KPI บนหน้าเจ้าหน้าที่คำนวณจากข้อมูลจำลอง ไม่ใช่ผลการลดภาระงานจริง
- ผลประเมินและ Badge ไม่ใช่ใบรับรองทางการ และไม่ได้รับการรับรองจาก สคบ.
