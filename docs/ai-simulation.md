# AI Simulation — AI-01 และ AI-02

> **AI Simulation ไม่ใช่ AI Model จริง** — ทำงานด้วยกฎที่กำหนดไว้ล่วงหน้า (Rule-based) ในเบราว์เซอร์เท่านั้น ไม่เรียก OpenAI / Claude / Gemini หรือ API ภายนอก ไม่ใช้ API Key ไม่ส่งข้อความออกนอกเครื่อง ผลวิเคราะห์เป็นคำแนะนำเบื้องต้นสำหรับการสาธิต **ไม่ใช่คำวินิจฉัยทางกฎหมาย** ไม่ใช่การอนุมัติโฆษณา และไม่ตัดสิทธิ์ผู้บริโภคในการร้องเรียนต่อเจ้าหน้าที่

ทุกหน้า AI แสดงป้าย **AI Simulation — ไม่ใช่ AI Model จริง** และกล่องข้อจำกัดความรับผิดชอบ (`AiDisclaimer`)

## หน้าจอและ Route

| Route | หน้าจอ |
|---|---|
| `/m/ai` | AI ผู้ช่วย SME — บริการ 2 รายการ + การวิเคราะห์ล่าสุด |
| `/m/ai/ad-checker` | AI-01 Advertising Compliance Checker |
| `/m/ai/complaint` · `/m/ai/complaint?case=CMP-…` | AI-02 Complaint Resolution Assistant (เลือกเคสจาก Complaint Center หรือพิมพ์เอง/ตัวอย่าง) |
| `/m/ai/history` | ประวัติการใช้งาน AI (ล่าสุด 20 รายการ) |

ทางเข้าอื่น: Merchant Home ส่วน **AI ผู้ช่วย SME**, เมนูผู้ประกอบการ, ปุ่ม **ให้ AI ช่วยวิเคราะห์** / **ร่างด้วย AI** ในหน้ารายละเอียดข้อร้องเรียนของร้าน

## โครงสร้างโค้ด

```
src/features/ai-assistant/
  types/ai.types.ts               ชนิดข้อมูลทั้งหมด
  rules/advertisingRules.ts       กฎโฆษณา (Regex + คำอธิบาย + คำแนะนำ + ข้อความแทน)
  rules/complaintRules.ts         คำสำคัญประเภทข้อร้องเรียน ระดับการติดตาม ข้อมูลที่ควรขอ คำแนะนำ
  services/advertisingAnalyzer.ts analyzeAd(), buildSegments(), validateAdInput()
  services/complaintAnalyzer.ts   analyzeComplaint(), extractFacts(), detectKinds()
  services/responseDraftGenerator.ts generateDraft()
  services/caseText.ts            แปลงเคสใน Mock Store เป็นข้อความ (ไม่รวมข้อมูลส่วนบุคคล)
  data/aiExamples.ts              ตัวอย่างโฆษณา 6 + ข้อร้องเรียน 6

```

Service ทั้งหมดเป็น **Pure Function** (รับข้อความ → คืนผล) ไม่แตะ Store จึงทดสอบได้โดยตรง (`tests/ai.test.mts`) · หน่วงเวลา 700 ms (`useSimulatedRun`) เพื่อแสดงสถานะ "กำลังวิเคราะห์" เท่านั้น และยกเลิกเมื่อออกจากหน้า

## AI-01 Advertising Compliance Checker

**Input:** 10–2,000 ตัวอักษร (ข้อความว่าง/สั้น/ยาวเกินแสดงข้อผิดพลาด) รองรับไทยและอังกฤษ (Regex ภาษาอังกฤษใช้ `\b` และไม่สนตัวพิมพ์)

### กฎตรวจสอบ

| Rule ID | ประเด็น | ความรุนแรง |
|---|---|---|
| `health-cure` | กล่าวอ้างการรักษาโรค (รักษาได้ทุกโรค, ชื่อโรคร้ายแรงคู่กับการรักษา) | High |
| `health-instant` | ผลลัพธ์รวดเร็วเกินจริง (เห็นผลทันที, เห็นผลใน x วัน, ลดน้ำหนัก x กิโล, instant results) | High |
| `health-no-doctor` | แนะนำให้ไม่ต้องพบแพทย์ / ใช้แทนยา | High |
| `absolute-guarantee` | รับประกันผลลัพธ์ (การันตีผล, ได้ผลแน่นอน, guarantee) | High |
| `absolute-safe` | ไม่มีผลข้างเคียง / ปลอดภัยที่สุด / no side effects | High |
| `absolute-100` | ตัวเลขยืนยันผล 100% (ยกเว้นวัสดุ เช่น ผ้าฝ้าย 100%, 100% cotton) | Medium |
| `superiority` | ดีที่สุด / อันดับ 1 / ถูกที่สุด / #1 โดยไม่มีแหล่งอ้างอิง | Medium |
| `promotion` | มีโปรโมชัน/ของแถม → ตรวจเงื่อนไข 4 ข้อ (ระยะเวลา จำนวน ค่าส่ง เงื่อนไข) | Low |
| `urgency` | เร่งการตัดสินใจ (ต้องซื้อด่วน, โอกาสสุดท้าย, เหลือเพียง x ชิ้น) — ไม่ถือว่าผิดโดยอัตโนมัติ | Low |
| `missing-promotion-terms` | โปรโมชันขาดเงื่อนไข (ขาด ≥ 2 ข้อ = Medium) | Low/Medium |
| `missing-price` | ข้อความ ≥ 30 ตัวอักษรแต่ไม่พบราคา | Low |

### ระดับความเสี่ยงเบื้องต้น

น้ำหนัก Low = 1, Medium = 2, High = 3

- **High** — มีประเด็นระดับ High หรือคะแนนรวม ≥ 6
- **Medium** — คะแนน ≥ 3 หรือมีประเด็นระดับ Medium
- **Low** — นอกเหนือจากนั้น

### ผลลัพธ์

- **Highlight** ในข้อความต้นฉบับ (แดง/ส้ม/เทา ตามความรุนแรง) — สร้างเป็น React Text Node ไม่ใช้ `innerHTML` จึงปลอดภัยจาก XSS
- รายการประเด็น: ข้อความที่พบ คำอธิบาย เหตุผล คำแนะนำ
- **Suggested Revision** — แทนคำกล่าวอ้างด้วยข้อความกลาง ๆ และช่อง `[วงเล็บเหลี่ยม]` ให้ร้านกรอกข้อมูลจริงเอง (เช่น `[ระยะเวลาโปรโมชัน]`) · ไม่สร้างฉบับแก้ไขเมื่อข้อความเกือบทั้งหมด (> 85%) เป็นคำกล่าวอ้าง หรือเมื่อผลเท่ากับต้นฉบับ
- เมื่อตัดข้อความทั้งวลี ระบบล้างเครื่องหมายที่ค้าง (เช่น ",.") และไม่เหลือคำค้าง (ทดสอบทั้งไทย/อังกฤษ)
- คัดลอก / แก้ไข / **วิเคราะห์ใหม่เพื่อเปรียบเทียบ** → ตาราง Before/After (ประเด็นที่ไม่พบแล้ว / ยังควรตรวจสอบ / ประเด็นใหม่)
- ผล Low **ไม่ได้แปลว่าโฆษณาถูกต้องตามกฎหมาย**

## AI-02 Complaint Resolution Assistant

**Input:** เคสจาก Complaint Center ของร้านที่ใช้งานอยู่ (เคสร้านอื่นหรือ ID ที่ไม่มีจะแสดงข้อผิดพลาด), ตัวอย่าง 6 เรื่อง หรือพิมพ์เอง

### การวิเคราะห์

| ส่วน | วิธีการ |
|---|---|
| ประเภท | Non-delivery, Product Mismatch, Damaged, Refund, Delivery Delay, Service, Other — นับคำสำคัญ (ประเภทหลัก = พบมากที่สุด) · "ไม่ได้รับ" เดี่ยว ๆ นับเป็น Non-delivery เฉพาะเมื่อตามด้วยสินค้า/คำลงท้าย — "ไม่ได้รับเงินคืน" = Refund, "ยังไม่ได้รับคำตอบ / ความสะดวก / การติดต่อ", "ไม่รับผิดชอบ" = Service, "ไม่ได้รับสินค้าที่ถูกต้อง" = Mismatch, "มาช้ากว่ากำหนด" = Delay |
| ข้อเท็จจริง | ดึงเฉพาะที่มีในข้อความ: เลขคำสั่งซื้อ จำนวนเงิน วันที่/ช่วงเวลา การกล่าวถึงภาพ/เลขพัสดุ — **ไม่เติมข้อเท็จจริงที่ไม่มี** |
| ระดับการติดตาม | **Urgent Review** (อันตรายต่อสุขภาพ/ความปลอดภัย, หลอกลวง/ติดต่อร้านไม่ได้) · **Attention** (ติดตามหลายครั้ง, เกิดนาน, มูลค่า ≥ 5,000 บาท, หลายประเด็น) · **Normal** — ไม่ใช่การประเมินความผิดของร้าน |
| ข้อมูลที่ควรขอเพิ่ม | ตามประเภท เช่น Non-delivery: เลขคำสั่งซื้อ วันที่ หลักฐานชำระเงิน เลขพัสดุ — แสดงเฉพาะข้อที่ยังไม่พบในข้อความ |
| แนวทางแก้ไข | ตามประเภท ไม่ตัดสินว่าฝ่ายใดผิด |

### ร่างคำตอบ (Response Draft)

- 6 ส่วน: คำทักทาย → รับทราบปัญหา → ขออภัยในความไม่สะดวก → สิ่งที่ร้านจะตรวจสอบ → ข้อมูลที่ขอเพิ่ม → ขอบคุณ
- 3 Tone: สุภาพและเป็นทางการ / เป็นมิตรและเข้าใจลูกค้า / สั้น กระชับ · คำลงท้าย ค่ะ/ครับ · ปุ่ม "สร้างสำนวนใหม่" สลับสำนวน
- อ้างถึงเฉพาะเลขเรื่อง/ข้อมูลที่อยู่ในเคส และข้อเสนอที่มีอยู่จริงใน Mock Workflow · **ไม่ยืนยันว่าร้านคืนเงินหรือจัดส่งแล้ว**
- กรณี Urgent ระบุว่าผู้บริโภคยังแจ้งเจ้าหน้าที่ได้ตามสิทธิ์

### การเชื่อมกับ Complaint Workflow เดิม

1. หน้าเคส `/m/complaints/:id` → **ให้ AI ช่วยวิเคราะห์** → `/m/ai/complaint?case=:id` วิเคราะห์อัตโนมัติ
2. **นำร่างไปใส่ช่องตอบกลับเคส** → บันทึกร่างใน `useAiWorkspaceStore.replyDrafts[caseId]` แล้วเปิดหน้าเคส
3. หน้าเคสใส่ร่างในช่องตอบกลับพร้อมแบนเนอร์ **"ยังไม่ได้ส่งถึงลูกค้า"** และปุ่ม "ไม่ใช้ร่างนี้"
4. ร้านค้าตรวจสอบ เลือกรูปแบบการตอบกลับ และกด **ส่งการตอบกลับ** เอง → `merchantRespond()` เดิม · **AI ไม่ส่งข้อความหรือเปลี่ยนสถานะเคสเอง**

## State และความเป็นส่วนตัว

| Store | เก็บ | Persist |
|---|---|---|
| `useAiHistoryStore` (`smetrust:v1:ai-history`) | ประเภท แหล่งที่มา (ชื่อตัวอย่าง/เลขเคส หรือ "ข้อความที่พิมพ์เอง") ผลสรุป ระดับ เวลา — **ไม่เก็บเนื้อหาที่ผู้ใช้พิมพ์** · ล่าสุด 20 รายการ · 4 รายการตัวอย่าง | ✓ |

**Clear History** ในหน้า `/m/ai/history` · **Reset Demo Data** คืนประวัติตัวอย่าง ล้าง Workspace และร่างที่ค้าง

## ข้อจำกัด

- เป็นการจับคำ/รูปแบบ ไม่เข้าใจบริบท — อาจพลาดคำกล่าวอ้างที่เขียนอ้อม หรือจับคำที่ไม่ใช่ปัญหา
- Suggested Revision เป็นการแทนคำตามกฎ อาจได้ประโยคที่ต้องเกลาเพิ่ม
- ไม่ครอบคลุมกฎหมายเฉพาะผลิตภัณฑ์ (อาหาร ยา เครื่องสำอาง ฯลฯ)
- หากพัฒนาต่อด้วย AI จริง ต้องมีการประเมินความถูกต้อง การคุ้มครองข้อมูลส่วนบุคคล และการทบทวนโดยผู้เชี่ยวชาญ
