# Limitations — ข้อจำกัดและสิ่งที่ระบบนี้ไม่ใช่

## ระบบนี้ไม่ใช่

- **ไม่ใช่ระบบยืนยันตัวตนจริง** — OTP, e-KYC, Biometric และ PIN เป็นการจำลองทั้งหมด ไม่เปิดกล้อง ไม่อ่านลายนิ้วมือ ไม่ส่ง SMS ไม่เชื่อมต่อ DOPA หรือผู้ให้บริการ e-KYC ใด ๆ
- **ไม่ใช่ระบบรับรองของหน่วยงานรัฐ** — ใบรับรอง Badge และ Trust Level เป็นแนวคิดเพื่อการสาธิต มีป้าย "ตัวอย่างใบรับรองสำหรับสาธิต" ทุกจุด ไม่ได้ออกหรือรับรองโดย สคบ. สภา SME หรือหน่วยงานใด
- **ไม่ใช่ Blacklist** — สถานะความเสี่ยง การระงับ และการเพิกถอนในระบบนี้เป็นข้อมูลสมมติ ไม่ได้สะท้อนการกระทำของร้านค้าจริง
- **ไม่ได้ส่งเรื่องร้องเรียนเข้าสู่ สคบ. หรือหน่วยงานใด** — "ส่งต่อเจ้าหน้าที่" หมายถึงภายในระบบสาธิตเท่านั้น
- **ไม่ใช่คำปรึกษาทางกฎหมาย** — เนื้อหาหลักสูตร ผล Screening Assistant และผล AI Simulation เป็นตัวอย่าง/คำแนะนำจำลอง ไม่ใช่คำวินิจฉัยทางกฎหมาย
- **AI Simulation ไม่ใช่ AI Model จริง** — AI-01/AI-02 เป็นกฎจับคำ/รูปแบบในเบราว์เซอร์ ไม่เข้าใจบริบท อาจพลาดหรือจับผิดได้ ผล Low ไม่ได้แปลว่าโฆษณาถูกกฎหมาย และ AI ไม่อนุมัติโฆษณาหรือส่งคำตอบแทนร้านค้า (รายละเอียด: `ai-simulation.md`)
- **ไม่ใช่ Marketplace หรือระบบชำระเงิน** — การคืนเงินเป็นเพียงข้อเสนอจำลอง ไม่มีการโอนเงิน

## ข้อจำกัดทางเทคนิค

- **Frontend-only**: ไม่มี Backend, Database, ORM หรือ API Server ข้อมูลเก็บใน `localStorage` ของเบราว์เซอร์ที่เปิดเท่านั้น ข้อมูลไม่แชร์ข้ามอุปกรณ์/เบราว์เซอร์ และอาจหายเมื่อล้างข้อมูลเว็บไซต์
- **Role Switcher ไม่ใช่ระบบยืนยันตัวตน** — ใครก็สลับเป็นเจ้าหน้าที่หรือ Admin ได้ · สิทธิ์ของแต่ละบทบาทบังคับ 2 ชั้นในแอป (RoleGate + `authorize()` ในชั้น Store — ดู [roles-permissions.md](roles-permissions.md)) แต่ไม่มี Backend จึงไม่ใช่การป้องกันฝั่งเซิร์ฟเวอร์ — **Frontend Permission และ Ownership Validation เป็นเพียง Prototype Simulation; Production ต้องตรวจ Role และ Resource Ownership ที่ Backend API** · Store ตรวจว่าร้านเป็นของ `session.operatorId` แล้ว แต่ Session เป็นข้อมูลจำลองที่แก้ได้ใน Browser จึงพิสูจน์ตัวตนไม่ได้ (KI-V2-33) และผล e-KYC จำลองยังตั้งได้ก่อนเข้าสู่ระบบ (KI-V2-34)
- **PIN เก็บเป็นข้อความธรรมดาใน localStorage** เพื่อการสาธิต ห้ามใช้ PIN จริง
- **อัปโหลดไฟล์เป็นการจำลอง** — เก็บเฉพาะชื่อและขนาดไฟล์ ไม่อ่านเนื้อหาไฟล์ ไม่ส่งไฟล์ไปที่ใด
- **Screening Assistant เป็น Rule-based อย่างง่าย** (จับคำสำคัญ/ตรวจช่องว่าง) ไม่ใช้ AI ภายนอก อาจจัดหมวดผิดได้ — เจ้าหน้าที่ปรับผลได้
- **QR Code** ชี้ไปที่ `origin` ของเครื่องที่เปิดระบบ (เช่น `localhost`) สแกนจากโทรศัพท์จะเปิดได้เฉพาะเมื่อเครื่องนั้นเข้าถึง URL เดียวกันได้ และข้อมูลจะเป็นข้อมูลตั้งต้นของเบราว์เซอร์โทรศัพท์ (ไม่ใช่ข้อมูลที่แก้ไขบนคอมพิวเตอร์)
- **การ Deploy แบบ Static** ต้องตั้ง Rewrite ทุกเส้นทางไป `index.html` เพื่อให้ลิงก์ตรง เช่น `/verify/...` ทำงาน — บน GitHub Pages ใช้ `404.html` (สร้างอัตโนมัติตอน build) ซึ่งเปิดหน้าได้ถูกต้อง แต่ HTTP Status ของลิงก์ตรงครั้งแรกจะเป็น 404
- **Bundle เดียวขนาดประมาณ 1.2 MB (gzip ~364 KB)** เนื่องจากไม่ได้แยก Code-split เพื่อความเรียบง่าย
- **ไม่มีโหมดสีเข้ม** และไม่ได้ทดสอบ Screen reader อย่างเป็นทางการ
- **การทดสอบอัตโนมัติ** (`npm test`) ครอบคลุม Workflow, AI Simulation, Demo Controller ทั้ง 8 Scenario + Full Journey และการ Render ทุกเส้นทาง (ดู `test-checklist.md`) · E2E บนเบราว์เซอร์จริง: Chromium (`npm run test:e2e`) และ WebKit ซึ่งเป็น Engine ของ Safari ทั้ง Desktop/iPhone/iPad (`npm run test:e2e:safari`) · ยังไม่ทดสอบบน Safari ของ macOS/iOS จริง, Firefox และอุปกรณ์จริง — ดู `known-issues.md`
- **Demo Controller**: Snapshot สำหรับ Restart Scenario มีเพียงชุดเดียว (ของเรื่องที่เล่นอยู่) · หากร้านจาก Scenario 2 ไม่อยู่ในสถานะรับรอง ระบบจะถามก่อนว่าจะกลับไปทำ Scenario 2 ให้ครบ หรือใช้ร้านตัวอย่าง M-001 (พร้อมหมายเหตุในตัวควบคุม)
- **การโหลดหน้า**: หน้าแยกไฟล์และโหลดล่วงหน้าทีละหน้าตอนเครื่องว่าง · โหลดไฟล์หน้าไม่สำเร็จหลังลองซ้ำ 3 ครั้งจะแสดง "โหลดหน้านี้ไม่สำเร็จ" ให้ผู้ใช้กดโหลดหน้าใหม่เอง (ไม่มี Automatic Reload) · Firefox รายงานการยกเลิกโหลดไฟล์เมื่อเปิดหน้าใหม่ทั้งหน้า (`NS_BINDING_ABORTED`) ซึ่งเป็นพฤติกรรมของเบราว์เซอร์ (KI-V2-37) · Listener `beforeunload` อาจทำให้ Firefox ไม่ใช้ Back-forward cache
- **E2E ภายใต้โหลดหนัก**: รัน 4 Workers บนเครื่องเดียว `vite preview` ตอบช้าถึงหลายวินาที (P95 ~1.6 s) หน้าแรกของ Scenario อาจ Render เกินเวลารอ 10 วินาทีเป็นครั้งคราว — เป็นข้อจำกัดของเครื่องทดสอบ ไม่ใช่การทำงานของแอป (KI-V2-38) · CI ใช้ 2 Workers
- ข้อความทั้งหมดเป็นภาษาไทย ไม่มีระบบหลายภาษา

## ข้อความกำกับที่ปรากฏในระบบ

- แถบ "ระบบสาธิต (Prototype)" ด้านบนทุกหน้า
- ป้าย "ตัวอย่างใบรับรองสำหรับสาธิต" บนใบรับรอง Badge และ Passport
- คำกำกับผล Screening ว่าเป็นคำแนะนำจำลอง ไม่ใช่คำตัดสินทางกฎหมาย
- คำกำกับ Dashboard/Reports ว่าเป็นข้อมูลสาธิต
- คำอธิบาย "ไม่พบข้อมูล ≠ กระทำผิด" และ "ข้อกล่าวหา ≠ ความผิด"
- ป้าย "AI Simulation — ไม่ใช่ AI Model จริง" และข้อจำกัดความรับผิดชอบในทุกหน้า AI
- แบนเนอร์ "ยังไม่ได้ส่งถึงลูกค้า" เมื่อมีร่างคำตอบจาก AI ในช่องตอบกลับ
